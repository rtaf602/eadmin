# ติดตั้งระบบ Login และเปิดเว็บบน GitHub Pages

ทำตามลำดับ 5 ส่วน ใช้เวลาราว 40 นาที ทำครั้งเดียว
ใช้ **บัญชี Google ที่แก้ไขไฟล์ LOGIN DATABASE และไฟล์ BACKLOG ได้** เพราะระบบหลังบ้านจะอ่านและเขียนสองไฟล์นี้ในนามบัญชีนั้น

> ระบบนี้ทดสอบกับตัวจำลองของ Google แล้ว แต่ **ยังไม่เคยรันบน Google จริง** ให้ทำส่วนที่ 5 (ทดลอง) ให้ครบก่อนใช้งานจริง
> ถ้าขั้นไหนไม่ตรงกับที่เห็นบนจอ ให้หยุดแล้วแจ้งผู้พัฒนา

## ส่วนที่ 1 — เตรียม Google Sheet

1. เปิดไฟล์ LOGIN DATABASE กด **Share** ตรวจว่า General access เป็น **Restricted** ทำแบบเดียวกันกับไฟล์ BACKLOG
   (ระบบหลังบ้านเข้าไฟล์ในนามเจ้าของ ผู้ใช้ทั่วไปไม่ต้องมีสิทธิ์ในไฟล์)
2. ในแท็บ `DATABASE LOGIN` ตรวจแถวของผู้ที่จะเป็น Admin ว่าคอลัมน์ **Role** เขียนว่า `Admin` และมี Username, ID Card ขรก., ID Card ปชช., BIRTH DATE ครบ
3. ไม่ต้องแก้หัวคอลัมน์ ระบบหาคอลัมน์จากชื่อหัวคอลัมน์ในแถวที่ 2 (`ชื่อ-สกุล`, `Role`, `Username`, `Salt`, `hash`, `วันสิ้นสุดการใช้งาน` ฯลฯ)

## ส่วนที่ 2 — นำไฟล์ขึ้น GitHub

4. เปิด repo บน GitHub กด **uploading an existing file** (หรือ Add file → Upload files)
5. ลากไฟล์และโฟลเดอร์ **ทั้งหมดที่อยู่ข้างในชุดไฟล์นี้** ไปวาง (`backend`, `docs`, `test`, `README.md`, `SETUP_TH.md` ฯลฯ) แล้วกด **Commit changes**

ไฟล์ในชุดนี้ไม่มีลิงก์ชีท ชื่อคน Username หรือรหัสผ่าน จึงขึ้น repo แบบ Public ได้ **อย่าเพิ่มข้อมูลเหล่านั้นลงใน repo ภายหลัง**

## ส่วนที่ 3 — สร้างระบบหลังบ้านบน Google Apps Script

6. เปิด https://script.google.com กด **New project** ตั้งชื่อโครงการ เช่น `eadmin602-backend`
7. ในไฟล์ `Code.gs` ลบของเดิมทั้งหมด แล้ววางเนื้อหาของไฟล์ `backend/Code.gs` ทั้งไฟล์
8. แก้ส่วน `SETUP` ด้านบนสุดของโค้ด **ในหน้า Apps Script เท่านั้น ห้ามแก้ในไฟล์บน GitHub**
   - `loginSheet` — วางลิงก์ไฟล์ LOGIN DATABASE
   - `backlogSheet` — วางลิงก์ไฟล์ BACKLOG
   - `superAdmin` — Username ของ Admin หลัก
   - `firstAdmins` — Username ของ Admin ที่จะตั้ง Password ครั้งแรก เช่น `['aaa_b', 'ccc_d']`
   - `siteUrl` — เว้นว่างไว้ก่อน จะใส่ในข้อ 19
9. กดรูปเฟือง **Project Settings** ทางซ้าย แล้วติ๊ก **Show "appsscript.json" manifest file in editor**
10. กลับไปที่ **Editor** เปิดไฟล์ `appsscript.json` ลบของเดิมทั้งหมด แล้ววางเนื้อหาของไฟล์ `backend/appsscript.json`
11. กด Save (รูปแผ่นดิสก์) เลือกฟังก์ชัน **setup** ในช่องเลือกฟังก์ชันด้านบน แล้วกด **Run**
12. Google จะขอสิทธิ์ ให้กด Review permissions เลือกบัญชี ถ้าขึ้นหน้าเตือนว่า Google ยังไม่ได้ตรวจสอบแอปนี้ ให้กด **Advanced** แล้วกด **Go to … (unsafe)** จากนั้นกด **Allow**
    (หน้าเตือนนี้ขึ้นเพราะเป็นสคริปต์ที่สร้างเอง สิทธิ์ที่ขอคือดูและแก้ไข Google Sheet ของบัญชีนี้)
13. ดูผลใน **Execution log** ด้านล่าง ต้องขึ้นว่า "ตั้งค่าเสร็จแล้ว: พบรายชื่อ … คน"
    ถ้ามีบรรทัด "คำเตือน" (เช่น Username ซ้ำ หรือแถวที่ข้อมูลไม่ครบ) ให้แก้ในชีทตามเลขแถวที่แจ้ง แถวที่ข้อมูลไม่ครบยังปล่อยไว้ได้ แต่คนนั้นจะยัง Login ไม่ได้
14. กด **Deploy → New deployment** กดรูปเฟืองข้าง Select type เลือก **Web app** แล้วตั้ง
    - Execute as: **Me**
    - Who has access: **Anyone**

    กด **Deploy** แล้วคัดลอก **Web app URL** (ขึ้นต้นด้วย `https://script.google.com/macros/s/` และลงท้ายด้วย `/exec`)
15. ทดสอบ: เปิด URL นั้นในเบราว์เซอร์ ต้องเห็นข้อความ `{"ok":true,"service":"eadmin602","ready":true}`

"Anyone" หมายถึงใครก็เรียกที่อยู่นี้ได้ แต่ระบบจะตอบเฉพาะผู้ที่ Login ผ่าน หรือมี One Time Link ที่ยังใช้ได้

## ส่วนที่ 4 — ใส่ที่อยู่ระบบหลังบ้านในเว็บ แล้วเปิด GitHub Pages

16. ใน repo บน GitHub เปิดไฟล์ `docs/assets/config.js` กดรูปดินสอ แล้วใส่ URL จากข้อ 14 ระหว่างเครื่องหมาย `' '`

        backendUrl: 'https://script.google.com/macros/s/xxxxxxxx/exec',

    กด **Commit changes**
17. เข้า **Settings → Pages** หัวข้อ Build and deployment ช่อง Source เลือก **Deploy from a branch**
    ช่อง Branch เลือก **main** และโฟลเดอร์ **/docs** แล้วกด **Save**
    (บัญชี GitHub แบบฟรีเปิด Pages ได้เฉพาะ repo ที่เป็น Public)
18. รอ 1–2 นาที ลิงก์ของเว็บจะขึ้นที่หน้า Settings → Pages (รูปแบบ `https://ชื่อบัญชี.github.io/eadmin/`) เปิดแล้วต้องเห็นหน้าเข้าสู่ระบบ

## ส่วนที่ 5 — ตั้ง Password ของ Admin ครั้งแรก และทดลอง

19. กลับไปหน้า Apps Script ใส่ลิงก์เว็บจากข้อ 18 ในช่อง `siteUrl` ของ `SETUP` กด Save แล้ว Run ฟังก์ชัน **setup** อีกครั้ง
20. เลือกฟังก์ชัน **createFirstAdminLinks** แล้วกด **Run**
    ใน Execution log จะมีลิงก์หนึ่งบรรทัดต่อ Admin หนึ่งคน **แต่ละลิงก์ใช้ได้ครั้งเดียวภายใน 30 นาที** ส่งให้เจ้าของบัญชีแต่ละคนทางช่องทางส่วนตัว
    ถ้าบรรทัดไหนขึ้นว่า "ข้าม" ให้แก้ในชีทตามเหตุผลที่แจ้ง แล้ว Run อีกครั้ง
21. เจ้าของบัญชีเปิดลิงก์ ตั้ง Password ของตัวเอง (ยาวอย่างน้อย 10 ตัวอักษร) และเลือกวันเดือนปีเกิดเพื่อยืนยันตัวตน
22. เปิดลิงก์เว็บ เข้าสู่ระบบด้วย Username, Password, หมายเลขบัตรประจำตัวข้าราชการ และวันเดือนปีเกิด แล้วกด **ไปหน้า Admin**
23. ทดลองกับบัญชีหนึ่งบัญชี: เลือกชื่อ เลือก Role กด **Generate One Time Link** เปิดลิงก์นั้นในอีกเบราว์เซอร์ ตั้ง Password แล้ว Login แล้วตรวจว่า
    - แท็บ `DATABASE LOGIN`: แถวของคนนั้นมี Role, Salt และ hash
    - แท็บ `LINK TOKEN`: มีแถวของลิงก์ คอลัมน์ Used เป็น TRUE
    - ไฟล์ BACKLOG: มีแถว `LINK_GENERATED` และ `PASSWORD_SET`
24. จับเวลาตั้งแต่กดเข้าสู่ระบบจนเข้าได้ แล้วแจ้งผู้พัฒนา (ดูหัวข้อ "สิ่งที่ควรรู้")

## การดูแลภายหลัง

- **อัปเดตโค้ดหลังบ้าน**: วางโค้ดใหม่ทับใน Apps Script แล้ว **Deploy → Manage deployments → รูปดินสอ → Version: New version → Deploy**
  ที่อยู่ `/exec` จะคงเดิม ถ้าสร้าง New deployment ใหม่จะได้ที่อยู่ใหม่ ต้องแก้ `docs/assets/config.js` ตาม
  ไม่ต้อง Run `setup` ใหม่ ค่าที่ตั้งไว้เดิมยังอยู่ (ช่อง `SETUP` ในโค้ดที่วางใหม่จะว่าง ซึ่งไม่เป็นไร)
- **เปลี่ยนค่าใน SETUP** (เช่น เปลี่ยน Admin หลัก หรือย้ายไฟล์ชีท): กรอก `SETUP` ให้ครบทุกช่องอีกครั้ง แล้ว Run `setup`
- **Admin ลืม Password ทุกคน**: กรอก `SETUP` ให้ครบ Run `setup` แล้ว Run `createFirstAdminLinks` จะได้ลิงก์ Reset ของ Admin ในช่อง `firstAdmins`
- **ปรับค่าของระบบ**: ส่วน `OPT` ใต้ `SETUP` ใน `Code.gs` เช่น `sessionHours` (เข้าสู่ระบบหนึ่งครั้งใช้ได้กี่ชั่วโมง ตอนนี้ 8), `minPasswordLength` (ตอนนี้ 10), `linkMinutes` (ตอนนี้ 30) แก้แล้วต้อง Deploy เป็น New version
- **ระงับการใช้งานของผู้ใช้**: ใส่วันที่ในช่องวันสิ้นสุดการใช้งานจากหน้า Admin หรือพิมพ์วันที่ในคอลัมน์ `วันสิ้นสุดการใช้งาน` ของชีทโดยตรง ผู้ใช้จะเข้าไม่ได้ตั้งแต่วันถัดไป

## สิ่งที่ควรรู้

- **สิ่งที่เก็บในชีท**: Role, Username, Salt และ hash ของ Password เท่านั้น ไม่มี Password ตัวจริงที่ใด Admin จึงดู Password ของใครไม่ได้ ถ้าผู้ใช้ลืมให้กด Reset Password
- **สิ่งที่ส่งไปหน้าเว็บ**: ยศ ชื่อ-สกุล ตำแหน่งงาน Username และ Role เลขบัตร วันเกิด Salt และ hash อยู่ที่ระบบหลังบ้านเท่านั้น การยืนยันตัวตนเทียบที่ระบบหลังบ้านแล้วตอบกลับแค่ถูกหรือผิด
- **สิทธิ์ตรวจที่ระบบหลังบ้านทุกครั้ง**: หน้าเว็บซ่อนหรือปิดปุ่มตามสิทธิ์เพื่อความสะดวก แต่คนที่แก้หน้าเว็บเองก็ยังถูกระบบหลังบ้านปฏิเสธ
- **Login ผิด 5 ครั้งติดกัน**: Username นั้นถูกพัก 15 นาที
- **กรอกวันเกิดผิด 5 ครั้งในหน้าตั้ง Password**: ลิงก์ถูกยกเลิก ต้องขอลิงก์ใหม่จาก Admin
- **ตอน Reset Password**: Password เดิมยังใช้ได้จนกว่าจะตั้ง Password ใหม่สำเร็จ จากนั้นทุกเครื่องที่ Login ค้างไว้ด้วย Password เดิมจะถูกให้ออก
- **ความเร็ว**: การ Login หนึ่งครั้งคำนวณ hash 5,000 รอบ ยังไม่ทราบเวลาจริงบน Google ถ้าช้าเกินรับได้ ลดค่า `pbkdf2Iterations` ได้ (Password ที่ตั้งไว้แล้วยังใช้ได้)
- **ยังไม่ได้บันทึกประวัติการ Login**: หน้าเข้าสู่ระบบใช้ข้อความคำเตือนเดิมที่ระบุว่าการ Login ทุกครั้งถูกบันทึก แต่ตอนนี้ระบบบันทึกเฉพาะการให้สิทธิ์ การตั้ง Password และการเปลี่ยน Role ลงไฟล์ BACKLOG
- **ยังไม่ได้เชื่อมกับหน้ารายงาน**: ระบบนี้ครอบคลุมการ Login หน้า Admin และหน้าตั้ง Password ส่วนการจำกัดสิทธิ์ของ Editor และ Viewer ในหน้ารายงานต้องทำเมื่อนำหน้าเหล่านั้นมาเชื่อม
