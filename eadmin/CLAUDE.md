# ระบบ Login และให้สิทธิ์ผู้ใช้งาน ฝูง.602 — คู่มือทำงานต่อ

ไฟล์นี้สรุปงานจนถึง 8 ต.ค. 2026 (รุ่นแรก ยังไม่เคยรันบน Google จริง) ให้ทำต่อได้โดยไม่ต้องมีประวัติการคุยเดิม
**ตอบผู้ใช้เป็นภาษาไทยเสมอ** ผู้ใช้เป็นเจ้าหน้าที่ของ ฝูง.602 บน.6 ไม่ใช่โปรแกรมเมอร์ ให้อธิบายผลเป็นภาษาคนใช้งาน ไม่ใช่ภาษาโค้ด

> **ห้ามเขียนลงในไฟล์ที่ git ติดตาม**: รหัสผ่าน ลิงก์หรือรหัสไฟล์ Google Sheet ชื่อคนจริง Username จริง เลขบัตร วันเกิด และที่อยู่ลิงก์ One Time Link
> repo นี้ใช้กับ GitHub Pages จึงอาจเป็น Public ค่าเหล่านี้อยู่ในส่วน `SETUP` ที่ผู้ใช้กรอกในหน้า Apps Script และใน Script Properties เท่านั้น
> ชุดทดสอบใช้คนและรหัสที่แต่งขึ้นทั้งหมด (`test/gas_sim.mjs`)

## 1. งานนี้คืออะไร

ส่วนเข้าสู่ระบบของ "สถานภาพอากาศยาน ฝูง.602" มีสามหน้าในโฟลเดอร์ `docs/` (GitHub Pages แบบ Deploy from a branch → `/docs` ไม่มีขั้นตอน build)
และระบบหลังบ้าน `backend/Code.gs` บน Google Apps Script (Execute as: Me, access: Anyone)

| หน้า | ทำอะไร |
|---|---|
| `index.html` | เข้าสู่ระบบด้วย Username, Password, หมายเลขบัตรประจำตัวข้าราชการ และวันเดือนปีเกิด หลังเข้าแล้วแสดง Role และตารางสิทธิ์ |
| `admin.html` | Admin เลือกชื่อ (ค้นหาได้ เลือกได้เฉพาะชื่อในชีท) แก้ Username เลือก Role กำหนดวันสิ้นสุดการใช้งาน แล้ว Generate One Time Link หรือเปลี่ยน Role |
| `set-password.html#token=…` | ผู้ใช้ตั้ง Password ของตัวเอง ยืนยันตัวตนด้วยวันเดือนปีเกิด |

ข้อมูลอยู่ใน Google Sheet ของผู้ใช้สองไฟล์ (ตั้ง Share เป็น Restricted):

- **LOGIN DATABASE** แท็บ `DATABASE LOGIN`: รายชื่อหลายกลุ่มในแท็บเดียว แต่ละกลุ่มมีแถวชื่อกลุ่ม (มีข้อความช่องเดียว) และแถวหัวคอลัมน์ซ้ำ
  ระบบหาคอลัมน์จากชื่อหัวคอลัมน์ (`COL` ใน `Code.gs`) ไม่ใช่จากตัวอักษรคอลัมน์ และเขียนเฉพาะ `Role`, `Username`, `Salt`, `hash`, `วันสิ้นสุดการใช้งาน`
- **LOGIN DATABASE** แท็บ `LINK TOKEN`: `Link ID | Token Hash | Username | Action | Created At | Expire At | Used | Attempts`
  `Used` เป็น FALSE / TRUE / REVOKED / EXPIRED / LOCKED
- **BACKLOG** (แท็บแรกของไฟล์): หนึ่งเหตุการณ์ต่อหนึ่งแถว เพิ่มต่อท้ายอย่างเดียว
  `Timestamp | Action | Event | กลุ่ม | ยศ ชื่อ-สกุล | Username | Username เดิม | Username ใหม่ | Role | Role เดิม | Admin ผู้ดำเนินการ | Link ID | Link หมดอายุ | หมายเหตุ`
  Action: CREATE / RESET / CHANGE_ROLE — Event: LINK_GENERATED, PASSWORD_SET, LINK_REVOKED, LINK_EXPIRED, VERIFY_FAILED, ROLE_CHANGED, END_DATE_CHANGED

## 2. กติกาที่ผู้ใช้กำหนด (8 ต.ค. 2026)

"Admin หลัก" คือบัญชีที่ผู้ใช้ระบุ Username ไว้ใน `SETUP.superAdmin` ระบบจำด้วยเลขบัตรข้าราชการของแถวนั้น (Script Property `SUPER_ID`) การเปลี่ยน Username ภายหลังจึงไม่ทำให้สิทธิ์หาย

1. เข้าหน้า Admin ได้เฉพาะผู้ที่มี Role `Admin`
2. **Admin หลัก**: เปลี่ยน Role ตัวเองไม่ได้ เปลี่ยน Role และ Reset Password ของทุกคนได้ เป็นคนเดียวที่ตั้งคนใหม่เป็น Admin และแก้ Username ได้ ไม่มีวันสิ้นสุดการใช้งาน Reset Password ตัวเองได้
3. **Admin คนอื่น**: เปลี่ยน Role และ Reset Password ของตัวเองได้ แก้ Username ของใครไม่ได้ (รวมของตัวเอง) แตะบัญชี Admin หลักไม่ได้ทุกกรณี
   เปลี่ยน Role หรือ Reset Password ของ Admin คนอื่นไม่ได้ ให้สิทธิ์ได้เฉพาะ Editor และ Viewer บัญชีที่ยังไม่มี Username ต้องรอ Admin หลัก
4. Username ที่แก้ บันทึกทับของเดิมตอนกด Generate One Time Link ห้ามซ้ำกับคนอื่น ถ้าซ้ำให้เตือนและไม่ออกลิงก์
5. Role บันทึกตอนกด Generate One Time Link บัญชีที่เคยตั้ง Password แล้ว (ดูจากคอลัมน์ hash) เลือกได้ระหว่าง Reset Password กับ เปลี่ยน Role (บันทึกทันที ไม่มีลิงก์)
6. One Time Link ใช้ครั้งเดียว อายุ 30 นาที หน้า Admin มีปุ่มคัดลอกและเวลานับถอยหลัง ลิงก์ใหม่ยกเลิกลิงก์เก่าของคนเดียวกัน
7. หน้าตั้ง Password: Username แก้ไม่ได้ Password กับ Confirm ต้องตรงกัน เลือกวันเดือนปีเกิด ก่อนบันทึกมีข้อความ
   "Password นี้ไม่สามารถเปลี่ยนแปลงได้เอง (หากต้องการเปลี่ยน Password ให้ติดต่อ Admin) คุณต้องการใช้ Password นี้หรือไม่"
   บันทึกเฉพาะ Salt และ hash **ห้ามเก็บ Password ตัวจริงที่ใด** สำเร็จแล้วแจ้ง "สร้าง Password สำเร็จ" หรือ "Reset Password สำเร็จ"
8. ผู้ที่ Login ได้ต้องมีครบ: ชื่อ-สกุล, ตำแหน่งงาน, ID Card ขรก., ID Card ปชช., BIRTH DATE, Role, Username, Salt, hash
9. เลยวันสิ้นสุดการใช้งานแล้ว Login ไม่ได้ ข้อความ: "สิ้นสุดระยะเวลาในการเข้าถึงข้อมูลของท่าน หากต้องการขยายระยะเวลา ให้ติดต่อ Admin" (ใช้ได้ถึงสิ้นวันที่ระบุ ช่องว่างคือไม่จำกัด)
10. Role: Admin ทำได้ทุกอย่าง — Editor บันทึกและแก้ไขรายงาน ดาวน์โหลดไฟล์ได้ — Viewer ดูอย่างเดียว ดาวน์โหลดไม่ได้
11. หน้าเว็บได้รับเฉพาะ ยศ ชื่อ-สกุล ตำแหน่งงาน Username และ Role เลขบัตร วันเกิด Salt และ hash ไม่ออกจากระบบหลังบ้าน

### การตัดสินใจที่ทำเองและแจ้งผู้ใช้แล้ว (ผู้ใช้ยังไม่ได้คัดค้าน)

- Password ยาวอย่างน้อย 10 ตัวอักษร; กรอกวันเกิดผิดครบ 5 ครั้งลิงก์ถูกยกเลิก; Login ผิด 5 ครั้งพัก Username นั้น 15 นาที
- Username: อังกฤษตัวเล็ก ตัวเลข จุด ขีดล่าง ยาว 3–30 ตัว ขึ้นต้นด้วยตัวอักษร
- เข้าสู่ระบบหนึ่งครั้งใช้ได้ 8 ชั่วโมง (`OPT.sessionHours`; ผู้ใช้ยังไม่ได้กำหนดตัวเลข)
- หน้า Admin มีช่องวันสิ้นสุดการใช้งาน (ผู้ใช้กำหนดเพียงว่าระบบตรวจจากคอลัมน์ในชีท)
- ตอน Reset Password รหัสเดิมยังใช้ได้จนกว่าจะตั้งรหัสใหม่สำเร็จ แล้ว session เดิมทั้งหมดของคนนั้นใช้ไม่ได้
- Admin ตั้ง Password ครั้งแรกผ่านลิงก์จากฟังก์ชัน `createFirstAdminLinks` ที่เจ้าของสคริปต์รันเอง ไม่ฝังรหัสเริ่มต้นไว้ที่ใด
- ช่องวันสิ้นสุดที่มีข้อความซึ่งไม่ใช่วันที่ ถือว่าเลยกำหนดแล้ว; Username หรือเลขบัตรข้าราชการที่ซ้ำกันสองแถว Login ไม่ได้ทั้งคู่

## 3. ระบบหลังบ้าน (`backend/Code.gs`)

- คำขอเป็น POST แบบ `text/plain` (ห้ามเปลี่ยนเป็น `application/json`: Apps Script ตอบ CORS preflight ไม่ได้) เนื้อหา `{ v, op, session?, … }`
  คำตอบ `{ ok: true, now, … }` หรือ `{ ok: false, error: { code, message } }`
- `op`: `info`, `login`, `me`, `link.info`, `link.use`, `admin.list`, `admin.link`, `admin.role` (สี่ตัวหลังสุดที่เขียนชีทใช้ `LockService`)
- **Password**: PBKDF2-HMAC-SHA256 เก็บเป็น `pbkdf2-sha256$<รอบ>$<hex>` จำนวนรอบอยู่ในค่าที่เก็บ จึงเปลี่ยน `OPT.pbkdf2Iterations` ภายหลังได้
- **Session**: ไม่เก็บฝั่งเซิร์ฟเวอร์ เป็นข้อความที่ลงลายมือชื่อ `{ เลขบัตรข้าราชการ, หมดอายุ, เครื่องหมายของ hash ปัจจุบัน }` อ่านแถวจากชีทใหม่ทุกคำขอ
  การเปลี่ยน Role วันสิ้นสุด หรือ Password จึงมีผลทันที หน้าเว็บเก็บ session ใน `sessionStorage` (หายเมื่อปิดแท็บ)
- **One Time Link**: token สุ่ม 32 ไบต์ อยู่หลัง `#` ของลิงก์ (ไม่ถูกส่งไปที่ GitHub) ในชีทเก็บเฉพาะ `sha256:<hex>`
- **การอ้างแถว** (`ref`): เลขแถว + ลายมือชื่อของ (แถว, เลขบัตร, ชื่อ) ไม่เปิดเผยเลขบัตร และใช้ไม่ได้ถ้าแถวเลื่อน
- **สิทธิ์** อยู่ใน `perm_()` ที่เดียว หน้า Admin มีสำเนาใน `perm()` เพื่อแสดงผลเท่านั้น ถ้าแก้กติกาต้องแก้ทั้งสองที่ และเพิ่มข้อทดสอบ
- ข้อความที่เขียนลงชีทต้องไม่ถูกอ่านเป็นสูตร ตัวเลข หรือวันที่: Salt ขึ้นต้นด้วย `s`, hash ขึ้นต้นด้วย `pbkdf2-`, Token Hash ขึ้นต้นด้วย `sha256:`
  Username `true` / `false` ไม่รับ วันที่และเวลาเขียนเป็นค่า Date จริง
- ฟังก์ชันที่เจ้าของรันจากหน้า Apps Script: `setup()` (อ่าน `SETUP` เก็บลง Script Properties ตรวจหัวคอลัมน์ รายงานแถวที่มีปัญหาเป็นเลขแถว) และ `createFirstAdminLinks()`
- Script Properties: `DB_ID`, `LOG_ID`, `SUPER_ID`, `SECRET`, `SITE_URL`, `FIRST_ADMINS`

## 5. กติกาการทำงานกับผู้ใช้

- อย่าเพิ่มความสามารถที่ผู้ใช้ไม่ได้ขอ ถ้าเห็นว่าควรมี ให้เสนอแล้วรอคำตอบ
- อย่าแก้ ลบ หรือจัดโครงสร้าง Google Sheet จริงเอง เว้นแต่ผู้ใช้สั่ง
- บอกเสมอว่าอะไรทดสอบแล้ว อะไรยังไม่ได้ทดสอบบน Google จริง
- ผู้ใช้เคยส่งรหัสผ่านเริ่มต้นของ Admin มาในแชต **ไม่ได้นำมาใช้และไม่ได้เขียนลงที่ใด** ถ้าผู้ใช้ส่งรหัสมาอีก อย่าใส่ลงโค้ด ชีท หรือเอกสาร

## 6. สถานะและงานค้าง

- รอผู้ใช้ติดตั้งและทดลองบน Google จริงตาม `SETUP_TH.md` สิ่งที่ต้องฟังผล: ขั้นตอนตรงกับหน้าจอจริงหรือไม่ Login ใช้เวลากี่วินาที ชีททั้งสามแท็บบันทึกถูกต้องหรือไม่
- **ยังไม่ได้บันทึกประวัติการ Login** ข้อความคำเตือนในหน้าเข้าสู่ระบบ (ของผู้ใช้เอง) ระบุว่าบันทึกทุกครั้ง แจ้งผู้ใช้แล้ว รอคำตอบว่าจะเพิ่มหรือแก้ข้อความ
- **ยังไม่ได้เชื่อมกับหน้ารายงาน** (DASHBOARD, ส่งรายงาน, ดูสรุป ในแบบร่างของผู้ใช้) เมื่อเชื่อม ทุกคำขอที่บันทึกหรือสร้างไฟล์ต้องเรียก `auth_()` และตรวจ Role ที่ระบบหลังบ้าน การห้ามดาวน์โหลดของ Viewer ต้องบล็อกตอนสร้างไฟล์ ไม่ใช่แค่ซ่อนปุ่ม
- ผู้ใช้ยังไม่ได้กำหนด: จำนวนชั่วโมงต่อการเข้าสู่ระบบหนึ่งครั้ง, "แก้ไขระบบ" ของ Admin หมายถึงอะไร, Editor แก้รายงานของคนอื่นได้หรือไม่
- ชีทจริงมีแถวที่ข้อมูลยังไม่ครบและแถวที่ยังไม่มี Username ผู้ใช้ให้ปล่อยไว้ (คนเหล่านั้นยัง Login ไม่ได้) `setup()` รายงานเลขแถวให้
